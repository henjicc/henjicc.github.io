# 经验库

> 读取时机：实现涉及下表主题时，先读命中的文件；要沉淀新经验时读本文件的写法。没有命中的主题不读。

经验是在实际项目或可靠资料中得到、换一个项目仍然成立的具体知识，限于特定技术栈、平台或领域。对所有项目都成立的做法写进对应细则；只对当前项目成立的写进 [`project-context.md`](../project-context.md) 的已知陷阱。

| 主题 | 何时读 | 文件 |
|---|---|---|
| 仓库隐私盘点与历史清理 | 盘点仓库里已有的私人内容；清理已跟踪的媒体、路径和夹具；改写已公开的历史；改动提交门禁脚本 | [`repo-privacy-cleanup.md`](repo-privacy-cleanup.md) |
| 验证闭环与代码评审 | 搭建或调整测试体系、代码评审流程、提交门禁；让 AI 自行验证或并行工作 | [`verification-loops.md`](verification-loops.md) |
| 性能优化 | 做性能专项、建立性能基准或性能门禁（如首页加载速度） | [`performance-hillclimbing.md`](performance-hillclimbing.md) |

## 写法

- 一个主题一个文件，开头写适用范围、来源和整理日期。
- 最有价值的是“坑”：AI 按常规思路做会出错的地方。读代码或凭常识就能知道的内容不写。
- 每条写清场景、现象、做法和原因。有原因，读的人才能判断新情况是否适用。写目标和约束，不逐步规定做法。
- 区分已验证和未验证。没有验证过的做法要标明，不写成结论。
- 去掉来源项目的名称、路径、标识符和秘密，换成占位符。
- 来自文章的经验用自己的话提炼做法并附链接。价格、型号、版本这类易变事实标注日期，使用前回原文核对。
- 新增或删除文件时同步上表。在业务项目中新增的经验，最终回复里提示用户可以回收到模板。

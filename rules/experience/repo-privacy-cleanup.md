# 仓库隐私盘点与历史清理

> 适用范围：盘点仓库里已有的私人内容、清理当前版本、改写已公开的历史。日常怎么避免见 [`AGENTS.md`](../../AGENTS.md) 和 [`private-content.md`](../private-content.md)。
> 来源：一个公开仓库的实际清理，事后经独立审查。整理于 2026-11。历史清理一节的平台行为以 GitHub 为准，使用前核对当前文档。

那个仓库在几个月里混进了几百个文件：用户出镜画面、带聊天窗口的桌面录屏、未发布作品片段、整段口播稿、带用户名的本机路径、素材盘路径、合作方的品牌名和项目名。每一次都不起眼：做草稿、截图验收、写开发记录、写测试时顺手用了真实内容，而这些文件所在的目录本来就会提交。

## 盘点

盘点期间只报告不修改，最后交给用户一张清单：每类内容在哪、多少个、敏感程度、能否直接删。范围由用户定，例如哪些名字算合作方、自己的邮箱是否放行。

- **列文件要关掉路径转义。** Git 默认把中文路径转义成八进制，按扩展名筛选会漏掉大半。用 `git -c core.quotepath=false ls-files`，或加 `-z`。
- **媒体要逐张看。** 文件名和目录名判断不出内容。把图片和视频取帧拼成缩略图联系表（写到 `.local/`），看完再分类：用户本人、桌面与聊天、作品与素材、生成图或网图、软件截图、软件资源与测试素材。
- **历史里删掉的也算。** `git log --all --diff-filter=A --name-only` 列出曾经加入过的文件，已不在当前版本的仍留在历史里。
- **本机路径有多种写法。** 除了 `/` 和 `\`，还有 JSON 里的 `\\`、URL 编码（`%5C`、`%3A`），以及 AI 会话目录名把 `:` 和 `\` 换成 `-` 的写法（形如 `D--Projects-repo`）。只搜一种会漏。
- **内容类靠人读。** 合作方名字、作品标题、口播原文常藏在测试夹具和开发记录里，没有固定格式可搜，要读文件。
- **图片可能内嵌在文本里。** 搜 HTML、Markdown、JSON 里以 `data:` 开头、带 `;base64,` 的内嵌内容；Jupyter 笔记本的输出里则是 `"image/png"` 字段。
- **排除误报。** 哈希值和小数会被当成证件号或手机号；测试里的假密钥、开源许可证里的作者邮箱不算泄漏。

## 清理当前版本

- 媒体用 `git rm --cached` 停止跟踪，本机文件保留；把它们所在的草稿、截图、证据目录加入忽略。
- 路径换成占位后，检查 JSON / JSONL 还能解析。编码混杂的文件（UTF-8 与 GBK 混用）单独处理，否则替换后变成乱码。
- 写死的本机素材路径改成读环境变量或不进仓库的本机配置。没配置时按“缺素材”处理；配置文件写坏时要报错，不能静默当成没配置。
- 合作方名字换成“客户A”这类代号，全仓库一致；只为某个项目写的脚本连文件名一起改。别误伤同名的开源库或公开产品名。
- 测试夹具分三种处理：
  - 真实数据只是当名字用的，换成通用假数据，同一文件内一致替换，保持测试关系不变。
  - 含真实口播、真实稿件的回归样本，挪到不进仓库的目录，测试改成有样本就跑、没样本就跳过。不要把测试一删了之，它保护的行为还在。
  - 不带身份信息的零散短句可以留，以后改到那段逻辑时再换。
- 在 Windows 上用内联 shell 改含反斜杠的内容容易出错，用编辑工具或单独的脚本文件。

## 提交门禁的坑

模板的 [`.githooks/pre-commit`](../../.githooks/pre-commit) 已经处理了下面这些；改动它或另写检查时不要重新踩。

- 钩子文件要有可执行位。Windows 不检查这一位，本机测不出来，到 macOS / Linux 上钩子会被直接跳过。Windows 上用 `git update-index --chmod=+x` 设置。
- 只在推送后的 CI 里检查太晚，内容已经进了远端历史。
- 提交时只检查新增的行。检查整份文件会让历史遗留内容拦住无关提交，逼人绕过钩子。
- 解析 diff 时，新增的行如果以 `++` 开头，会和文件头 `+++ b/…` 混淆而漏过，要区分文件头和内容。
- 在 git worktree 里 `--show-toplevel` 是工作树目录，主仓库目录要从 `--git-common-dir` 得到，两个都要拦。
- 仓库或素材目录在盘符根目录时，“所在目录”会退化成整个盘，匹配范围过宽，要跳过。
- 私人词条不能写进检查脚本或任何已跟踪文件，否则检查本身成了泄漏源。存到 `.git/config` 或不进仓库的本机文件。
- 用户的 Git 邮箱本来就在每个提交的作者信息里，拦它只有误报。
- 检查脚本里任何一步命令失败都要按拦截处理。管道和进程替换默认吞掉失败，`git diff` 因为缺少 textconv 程序报错、`grep` 返回 2 时，得到的是空结果，脚本会当成“没有问题”放行。
- 只按扩展名认媒体挡不住压缩包和没列出的格式；只扫 Git 认为是文本的内容，会漏掉标了 `-diff` 或 `binary` 属性的文件和 UTF-16 文本（Windows PowerShell 5 的重定向默认产出）。把“内容是二进制”也当作判据，文本一律强制按文本读。
- 用 `LC_ALL=C` 按字节匹配。GNU grep 在 UTF-8 环境下遇到 GBK 等非法字节的行，只报“binary file matches”而不输出命中行。
- 不用 `grep -iF`。Git for Windows 自带的 grep 3.0 在 `LC_ALL=C` 下 `-i` 和 `-F` 一起用会直接崩（abort），门禁按出错处理，所有提交都被拦下。要按原文、不分大小写匹配时，先转义正则特殊字符，再用 `-iE`。
- 目录名里的空格、点和中文，在 URL 编码里变成 `%XX`，在会话目录名里全部变成 `-`，按原文匹配会漏。
- pre-commit 钩子管不到无冲突的合并、rebase、cherry-pick 和提交信息；这些靠 CI 的全量检查兜底，提交信息靠自己看。
- 钩子脚本要固定为 LF 换行（`.gitattributes`）。Windows 默认把检出文件转成 CRLF，脚本会直接跑不起来，逼人绕过。
- 自测要断言拦截的原因而不只是“没提交成功”，并用变异测试检验：把脚本里的关键判断逐个改坏，自测应当失败。
- 每次改动后做反向测试：违规内容确实被拦，约定的假数据确实能过。模板里是 `.githooks/selftest`。

## 已经公开过的历史

每一步都要用户明确同意。下面的顺序是为了任何一步出错都能退回。

1. 先把仓库设为私有止损。告诉用户这挡不住已有的 fork：fork 继续公开，里面是它 fork 或最后同步那一刻的历史。用 `gh api repos/<仓库>/forks` 看各 fork 的创建和推送时间，判断哪些内容可能已经在 fork 里。
2. 在单独的镜像克隆（`git clone --mirror`）上用 `git filter-repo` 试跑，不在工作仓库上操作。核对三件事再推送：清理后最新版本的树哈希与原来完全一致（当前版本已先清理干净时）；历史里残留的私人内容为零；提交数没有少。
3. 强制推送全部分支和标签。`refs/pull/*` 是只读的，推不上去，旧提交仍能通过 PR 访问。
4. 用户的工作仓库只用 `git update-ref` 把分支指针移到新历史上。最新版本内容相同，工作区不受影响；`reset --hard` 会丢掉未提交的改动，包括其他会话正在做的。只存在于旧历史上的本机分支不要推送。
5. 提醒用户：其他设备和协作者删掉旧克隆重新克隆。在旧克隆里 pull 会把旧历史合并回来，再一推就前功尽弃。
6. 重新公开之前，由用户联系 GitHub Support 清除缓存视图和 PR 对旧提交的引用。仓库保持私有时这一步不急。
7. 收尾验证：从远端重新完整克隆（含 PR 引用），把本机所有私人文件逐个算 Git 对象哈希，与克隆里的全部对象比对，确认一个都不在。
8. 泄漏过的密钥一律视为已失效，立即轮换，不依赖历史清理。

清理做完后，请一个不带当前上下文的审查者独立复查清理结果和门禁。来源项目的独立审查找出了十一个真实问题，其中三个会让防线失效。
